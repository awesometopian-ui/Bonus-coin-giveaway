# Bonus Coin Giveaway

A simple, mobile-first giveaway website:

- **Public site** — a Home page and a Rewards page. Visitors tap **Claim Reward** and fill in whatever fields the admin has configured (wallet address, account details, or anything else — fully flexible).
- **Admin panel** (`/admin`) — completely separate from the public site, no link to it appears anywhere on the public pages. The admin logs in and can:
  - Edit the welcome message and site name
  - Create/edit/delete giveaways and switch which one is live
  - Add, edit, delete, reorder, and enable/disable custom submission fields (any number, any names)
  - View submissions privately
  - Pick a winner manually or at random

## Running locally

```bash
npm install
cp .env.example .env
# edit .env: set SESSION_SECRET, ADMIN_USERNAME, and generate ADMIN_PASSWORD_HASH
npm run hash-password -- "your-strong-password"
npm start
```

Visit `http://localhost:3000` for the public site and `http://localhost:3000/admin` for the admin panel.

## Deploying to Render

### Option A — using `render.yaml` (recommended)

1. Push this project to a GitHub/GitLab repo (or use Render's "Deploy from a zip/folder" if offered — otherwise push to a Git repo first, since Render deploys from Git).
2. In Render, choose **New > Blueprint** and point it at the repo. Render will read `render.yaml` and create the web service automatically, including a small persistent disk for the data file.
3. When prompted, set the environment variables:
   - `ADMIN_USERNAME` — your admin login username
   - `ADMIN_PASSWORD_HASH` — generate with `npm run hash-password -- "your-password"` and paste the bcrypt hash (never the plain password)
   - `SESSION_SECRET` is auto-generated by the blueprint

### Option B — manual Web Service

1. New **Web Service** → connect your repo.
2. Build command: `npm install`
3. Start command: `npm start`
4. Add environment variables: `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH` (see above).
5. **Important — data persistence:** this app stores its data (settings, giveaways, fields, submissions) in `data/db.json` on disk. Render's filesystem is ephemeral by default, so add a **Disk** in the service settings, mounted at `/opt/render/project/src/data`, so your data survives restarts and redeploys. (`render.yaml` already does this for Option A.)

## Generating the admin password hash

Never put a plain-text password in an environment variable or in code. Generate a bcrypt hash instead:

```bash
npm run hash-password -- "your-strong-password"
```

Copy the printed hash into `ADMIN_PASSWORD_HASH`.

## Project structure

```
server.js              Express app setup
db.js                  File-backed data layer (settings, giveaways, fields, submissions)
middleware/auth.js     Admin session guard
routes/public.js       Home + Rewards pages, claim submission
routes/admin.js        Admin authentication + management routes
views/                 Public EJS templates
views/admin/           Admin EJS templates (separate from public views)
public/                Static CSS/JS
data/db.json           Generated at runtime; holds all persisted data
```
